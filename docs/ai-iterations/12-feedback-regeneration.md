# 12 按反馈重新生成一批练习题

> 迭代日期：2026-11-14

> 模型：`deepseek-flash`  
> 对应提交：`27e6152`  
> 相关测试：`pytest -q` 77 项、`npm run test:browser` 23 项、`npm run build`  
> 对话快照：[本次练习改造导出](exports/dsh-session-2026-11-14-practice-redesign.md)

## 用户 Prompt（原话）

> 可以增加一个功能，如果用户不满意当前生成的题目，可以像系统提交反馈，系统根据用户的反馈和当前的知识点重新生成一批练习题。  
> 你觉得怎么样

在确认方案后，用户明确不接受额度限制：

> 我觉得不需要限制同一练习链生成的次数。

## AI 建议

- 做成「整批反馈」而不是复用单题「质疑此题」：单题质疑负责事实性错误，整批反馈负责难度、表述、题型和重复度。
- 新题保留当前知识点，排除旧题题干；仍走 10 题、2 真题 + 8 模拟、真题不足模拟补齐。
- 只有**未出报告、没有未完成核查/巩固**的练习可以换题；部分作答会清空，并提示本次未完成不积分。
- 初版建议限制 3 次，用户否决后改为**不限制次数**；只用前端 `busy` 防止请求中重复点击。
- 新练习与旧练习同一学习会话，旧练习保留在数据库中；接口返回 202，前端沿用现有轮询。

## 实现

- 后端新增：
  - `FeedbackRequest`，反馈 1–500 字；
  - `POST /api/quizzes/{quiz_id}/regenerate`；
  - 校验 owner、status、已有报告、pending review、blocked drill；
  - 用旧题 topic 生成 `feedback_scope`，用 `store.seen_stems` 排除旧题；
  - 新建同 version / learning session 的练习，写入 `learner_feedback`；
  - `generate_job`、`build_quiz` 增加 `learner_feedback`，并写入模型 scope；
  - `DRAFT_PROMPT` 要求按反馈调整难度、表述、题型或情境。
- 前端新增：
  - 练习头部「换一批题」；
  - 内联反馈表单、快捷标签、部分作答警告；
  - 成功后重置到新练习第一题，失败保留反馈。
- 不做次数计数，不返回 429。

## Bug 与修复

- **报告后换题会破坏成绩语义**：限制为报告前使用；报告后继续使用现有「重新练习」。
- **部分作答被静默丢弃**：表单在 `answered > 0` 时明确提示「清空当前作答，本次未完成不会获得积分」。
- **请求中重复提交**：`run` 增加布尔返回值，提交期间按钮禁用；成功后才关闭表单并清空反馈。
- **测试插入边界**：新增测试时一度覆盖了后续挑战测试的函数头，`pytest` 直接收集失败；恢复测试函数并补跑全部用例。
- **不限次数**：后端不保存 `regenerations` 计数；测试连续两次重新生成都成功，确认没有 429。

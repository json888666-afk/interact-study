# 02 · 对话修改与版本管理

**状态：文字修改、就绪后自动切换和本地版本恢复已实现。**

可在 [Codex 对话原文导出](04-codex-transcript.md) 中查看这组设计与后续验收的完整消息。

## 原始需求与设计回应

同一轮对话同时提出动态代码生成和版本管理。完整原文见[从预设工具改为动态生成](01-lesson-preview.md#从预设工具改为动态生成)。

用户要求在不满意时通过对话重新生成代码，确认后启用满意版本，并在本地保留此前的代码以便继续修改。Codex 提出用当前版本、候选版本和历史快照区分这三种状态。新代码先预览，再由用户确认。此前启用的版本可以恢复。

## 初版实施与验证

用户在执行计划中给出的实施指令原文如下。

> 推送验证完成后，继续下一阶段「对话修改与版本管理」，从真实的修改请求、候选版本预览和回退验证开始积累第二条实施记录。

实现记录见 Git 提交 `Add conversation-based lesson revisions and version history`。修改请求携带原始问题、用户意见和正在预览的代码。候选内容在同一沙箱预览，用户确认后写入版本历史。恢复旧版只切换当前版本指针，仍可重新启用较新的版本。

- API 验证「增加暂停按钮」会与原始问题和选中版本一起发给模拟模型。空白修改请求返回输入校验错误。
- 浏览器验证候选交互、确认、刷新、恢复版本 1，再次刷新后版本 2 仍可恢复。
- 浏览器主动注入异常候选脚本，确认按钮保持禁用，放弃候选后原版可继续操作。此项为故障注入测试。
- 前端构建、13 项 API 测试和 8 项 Edge 测试均通过。候选生成采用模拟模型响应，真实模型联调仍需配置。

## 调整现场演示流程

用户在讨论真实 API 接入时提出：

> 但我觉得直接把api接进去，不需要预览，这样也方便我展示最终的那种效果，你觉得呢。我准备调用deepseekv4.1-flash模型的api

Codex 对自动切换的回应：

> **自动切换**就是新版加载成功后，画布直接显示新版，省掉现在的「确认此版本」按钮。旧版仍可从历史恢复。如果新版加载失败，画布就继续显示旧版。

用户确认：

> 我觉得一起实现就好，这样第一部分的学习功能就有个雏形了。

最终界面在后台加载新版，收到就绪信号后直接启用。故障注入测试先把旧画布的滑块调到 `-1`，再让新版脚本报错，确认旧画布的滑块值与版本历史都保持原状。引用仅收录与需求有关的文字。

使用 DeepSeek 官方 `deepseek-flash` 完成真实浏览器联调。现场输入向量投影问题后，生成的 SVG 和滑块可操作。随后要求增加「投影长度实验」标题，新版自动显示并保留滑块，可从历史恢复到初版。前端构建、14 项 API 测试和 8 项 Edge 自动化测试均通过。
